## Supplied requirements

**Outcome:** a working client-server dashboard with live-streaming market data and persistent records.

- **Live visualization.** Connect to Yahoo Finance and use a charting library to display updating candlesticks and corresponding volume. Use WebSockets for real-time communication. Make the data source, age, and feed status visible.
- **Persistence and replay.** Store market observations in SQLite so that they can be retrieved and replayed. Preserve observation identity, source and receipt times, revisions, and whether a candle is complete. Explain and test how duplicate, revised, and out-of-order observations are handled.
- **Working evidence.** Demonstrate the path from the live source through the backend to the chart and database, including an unavailable-feed condition. Maintain the README, agent instructions, and design notes describing the data flow and SQLite schema. Document database initialization and startup without exposing credentials.

**CSV loading is ungraded in-class practice.** The Part 4.1 deliverable must demonstrate live streaming. Recorded observations support development and replay when the market is closed.

## Implementation update — November 14, 2026

The original audit above is retained as the starting point. Live mode now loads `/api/history` from SQLite observations through the shared one-minute and exchange-session aggregation. An empty store returns an empty candle list and an explicit waiting state, while the browser still subscribes for updates. CSV is used only when `MARKET_CANDLE_FILE` is explicitly configured for a labeled development fixture. No Yahoo HTTP history backfill has been added; the chart contains captured observations only.

Receipt cutoffs now govern both observations and their corrections. The live hub broadcasts all changed candles, including older late/revised minutes, and a one-second evaluation task closes forming candles without requiring another tick. Changed candle and completion states are retained in the additive `candle_states` SQLite table. Source observations and receipt audit rows are preserved.

Volume uses available cumulative `day_volume` differences within the same UTC date and requires a baseline in the preceding minute. Missing totals, missing adjacent baselines, gaps, and decreases return `null`, rendered as Unknown. `last_size` is preserved for audit but is not summed: a quote stream does not establish a complete trade tape. This addresses honest handling and repeat-safe calculation; **real corresponding volume remains unverified when Yahoo omits the field**. No volume values are fabricated.

Closed-market evidence: the offline browser SmokeTest passed; the focused recorded-history test passed for empty state, receipt cutoff, repeat, late broadcast, revision, timer completion, volume uncertainty, disconnect, and database reopen. The real FastAPI WebSocket fixture and Vue browser showed the expected 15:00 OHLC `100/103/100/101`, volume 11 shares, and an upstream disconnect with the local socket still connected. All inputs to those checks were labeled TEST DATA. A five-second actual Yahoo probe opened the connection but received no message. The actual regular-session source-to-chart check and actual volume-bearing Yahoo observation are still pending. Details are in `verification.md`.
