# 18 — Offline browser SmokeTest

Implement the `SmokeTest` in `AGENTS.md` as one documented command. It must start FastAPI and Vue, wait for readiness, open a real browser, perform user operations, return nonzero on unmet expectations, and close processes/browser even on failure. Inspect local test tools, runtimes, manifests, and lockfiles; obtain approval before new software or dependency changes.

Run against a fresh isolated SQLite account and deterministic recorded observations, candles, and fill prices. Stub Yahoo and the model boundary. In Vue, replay a recorded session, add an SMA, change its window, and compare its displayed value with a hand calculation. Click **Ask about chart**, verify decodable chart pixels and matching symbol/cutoff at the provider boundary, show known answers, and confirm no fill. Repeat with a provider failure and verify the visible error state.

Start browser paper automation at $1,000 and zero fees. Use four shares for a buy at $100, one share for a partial sale at $110, then close three at $105. Confirm $1,025 cash, zero shares, $25 realized and $0 unrealized P&L in Vue and SQLite. Check a reviewer veto, duplicate event, and a candle after Stop create no extra fill/order. Run the command twice from fresh accounts. Record commands, expected and observed values, and failure evidence in `docs/verification.md`. Run the same command on pushes through GitHub Actions with offline fixtures. Keep live Yahoo, image-model, and two-way voice checks separate. `SmokeTest` reports failures without source edits; `AutoLoop` may make a scoped correction and rerun up to five cycles.
